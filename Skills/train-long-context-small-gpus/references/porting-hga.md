# Port HGA and low-VRAM training to another model

The reusable idea is a bounded active segment plus routed attention over a much longer KV history, with frozen quantized weights and LoRA updates. HGA is designed as a model-portable method; it still needs an attention wrapper and memory plan for each architecture. The team's tests include working contexts around 256K tokens. Architectures without standard KV attention, unsupported quantized kernels, different positional schemes, or insufficient host RAM require design changes.

1. **Specify the model contract.** Pin checkpoint and tokenizer revisions; list decoder blocks, attention types, KV head geometry, position encoding, cache semantics, auxiliary heads, vision/audio modules, and the model's native context limit. If the model is hybrid, route only suitable full-attention layers and preserve the native recurrent/linear state.
2. **Implement the attention wrapper.** Preserve the checkpoint's Q/K/V/O projections and norms, causal masking, RoPE/position offsets, grouped-query head mapping, chunk boundaries, and exact token attention inside selected chunks or groups. Chunk/group summaries choose regions; they are never output values. Keep sink and recent windows visible, then route the middle history. Implement deterministic cache commit/rewind so no-grad forward and backward replay see the same prefix, including a partial final chunk.
3. **Size the machine.** Compute frozen quantized weight, embedding/head, LoRA/optimizer, activations, vocabulary logits, hot KV, communication, CUDA workspace, and RAM cold-KV costs. Choose a measured resident-stage split for multi-host training. Qwen3.8's 33/31 split is not a default for other models.
4. **Prove training fidelity.** On a tiny checkpoint compare unsegmented reference and segmented path for loss and LoRA gradients across segment boundaries. Verify cache reset between examples, complete label alignment, finite optimizer steps, and adapter load on the intended serving checkpoint. Then run real-hardware short and long smoke samples, including a near-limit trajectory. Track peak VRAM and host RAM/swap. The HGA training paper reports a chunk-shared routing side channel after substantially longer training; the team's tests found no significant effect through 100M training tokens. For longer runs or pretraining, include strict causal-leakage checks rather than extrapolating the short-run result.
5. **Measure quality.** Compare a model-specific dense-attention short-context baseline with HGA on short samples, then assess retrieval/edit tasks that genuinely require distant context. Record effective context used; a configured `seq_len` alone does not prove long-context quality.

For Qwen3.5-4B the local example is `Experiments/hga_qlora`: 24 linear-attention and 8 full-attention layers, HGA on the latter, 4-bit NF4 QLoRA, and 2048-token segments on a tested 16 GB Turing-class GPU. For Qwen3.8-27B use the dual project instead. Keep model-specific commands and checkpoint formats separate.
